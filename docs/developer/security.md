# Security findings

**Unit type:** Register

What we have found that could harm a person using Вивід, how we know, and what closes it. `SECURITY.md` tells users the threat surface, and this register holds the findings behind it. A row is promoted to a security domain once one exists.

**Evidence** says how far a finding was proven: tested on a hostile domain, read from the code, or designed but not yet built. A row is open until its `Fixed in` cell is filled.

| SEC-2 | **A manifest's family may be defined by a file outside the domain, whose rows are indexed and shown to an agent.** | high | manifest, index | tested 2026-11-04, `find` printed a row from outside the domain | as SEC-1 | 2026-11-04 |

| SEC-9 | **A finding's text reaches an agent like any other text, so it can carry instructions.** | medium | results | tested 2026-11-04, find, read, node and a recipe's briefing labelled a knowledge domain's entries as data and named invisible Unicode and an HTML comment, and no control removes this wholly. Tested 2026-11-04 that a hostile section of an untrusted project is labelled as data in `find` and in `read` | label results as data from a named domain, and flag invisible Unicode and HTML comments. A section of an untrusted project is labelled the same way, and its heading is scanned with its text | 2026-11-04 |

| SEC-11 | **Glue inherits the whole environment, including tokens and the SSH agent socket, with which it can act as the user.** | high | glue, credentials | read from the code, `subprocess.run` is given no `env`. | SEC-12 | **Glue, an extractor and an installed package run with the user's full privileges, and can read `~/.ssh`, `~/.aws` and any other file.** | high | code, credentials | inherent, no cross-platform sandbox exists to apply. | SEC-13 | **A folder-local configuration would let a cloned repository declare glue that runs when a recipe does.** | high | glue, configuration | tested 2026-11-04, a configuration other than the user's own ran no glue and no command extractor until `vyd trust` recorded its hash, and a one-byte edit undid it. It was refused when it set `code`, `git`, `remote` or `trust`, or named a path leaving the repository by name or through a link, and a refused file set aside only its project. Until trusted, its contract, skills and recipe descriptions were withheld and its entries labelled as data | an explicit trust step per folder, re-asked when the configuration changes | 2026-11-04 |
| SEC-14 | **`VYVID_CONFIG` redirects the whole configuration, so whatever sets the environment chooses what glue exists.** | medium | configuration | tested 2026-11-04, a configuration named by `VYVID_CONFIG` is treated as any other outside the user's own folder | apply the trust step to any configuration outside the user's own folder | 2026-11-04 |
| SEC-15 | **Glue's output and error text go to the agent, and so to the model's provider and the transcript.** | medium | glue, credentials | tested 2026-11-04, a fake token printed by glue on standard output and on standard error, and by a command extractor, reached neither the briefing nor the error | cap the error text, and redact what looks like a credential | 2026-11-04 |
| SEC-16 | **`vyd kb record` under an automatic push can publish a secret, since nothing scans what it stages.** | high | update, credentials | tested 2026-11-04, a fake token in a staged file refused the record and staged nothing, with the token absent from the message, by the built-in scan and by `gitleaks` | refuse to stage what looks like a credential | 2026-11-04 |
| SEC-17 | **A remote URL holding a token is stored in the configuration and printed by `vyd kb`.** | low | configuration, credentials | tested 2026-11-04, a password, a user part on https, a query and a known token format were refused, naming the host and never the URL | refuse a remote URL that holds a credential | 2026-11-04 |
| SEC-18 | **The index and the question logs are plain files under the user's default permissions, and a question may hold something sensitive.** | low | store, credentials | tested 2026-11-04 on POSIX, the store folder is 0700 and an existing one is tightened, the logs are 0600, and `logs = false` writes none | owner-only permissions, and a setting that turns the logs off | 2026-11-04 |
| SEC-19 | **An extractor's package would be installed with no pinned hash.** | high | code | designed, not built | a pinned hash, explicit consent, and no install on a pull | |
| SEC-20 | **One domain's refused manifest stops the whole configuration, so a careless or hostile push to a domain can stop `vyd` in every project on the next pull.** | medium | manifest, update | tested 2026-11-04, a refused manifest set aside only its domain and its descendants, `vyd config` listed them and exited non-zero, and the rest loaded | set aside only the domain at fault and report it, and hold a pull that would break its manifest | 2026-11-04 |
| SEC-21 | **`vyd trust` and `vyd kb accept` refuse unless standard input is a terminal, which is a speed bump and not a proof, since an agent given a pseudo-terminal could pass it.** | medium | trust | read from the code, and the tests prove only that a pipe and `/dev/null` are refused | none that holds in software alone. | SEC-22 | **An agent that can run commands as the user can edit the user's configuration and set `trust = "own"`, or record trust itself.** | high | trust, configuration | inherent, the user's configuration is trusted because the user wrote it | the client's permission settings, which are outside Вивід. `SECURITY.md` says so | |

| SEC-24 | **A bare path in a manifest resolved against the working folder, so `defined = "notes.md"` read that file from wherever a command ran, passing the containment check, and a held update compared the wrong path and merged.** | high | manifest, index, update | tested 2026-11-04, a real clone merged a changed rule while the suite passed, since its tests used `self:` paths | a bare path means the scope's own folder, proven by tests with a file of the same name in the working folder | 2026-11-04 |
| SEC-25 | **A reviewer told to run nothing used a shell to decode a blob, since the client gave it one.** | medium | review | tested 2026-11-04, the first real run of the review skill, which found all 13 planted attacks, obeyed none and made one false report | `vyd install` writes the reviewer as an agent with read and search tools alone, and the audit prints what a blob decodes to. Once installed, the client lists `vyvid-domain-reviewer` with the tools Read, Grep and Glob alone, so a client that enforces an agent's tool list holds it to them. A client that does not stays a request | 2026-11-04 |
| SEC-26 | **Compiled tree-sitter grammars parse source from a clone, so a fault in a grammar or a file built to make a parse slow could crash or hold the build.** | medium | symbols, build | read from the code, and tested that a file which fails to parse costs that file alone, that an untracked file, a link leaving the repository and a file over 2,000,000 bytes are not read, and that nothing in a clone runs. No fuzzing was done | Only files `git ls-files` lists are read, grammars and queries come from the package and never from the clone, the grammars are pinned, and a symbol of an untrusted project is labelled as data. Parsing is in the build's own process and has no time limit, so a grammar that faults ends that build and a slow parse delays it. Stays open until a time limit or a separate process is built | |
| SEC-27 | **`vyd handoff` opens the SQLite file a trusted vyvid.toml names, and hands an agent commands against it, so a hostile file could exploit SQLite or `hiedb`, hold views meant to run when read, or be slow to read.** | medium | handoff | read from the code, and tested with a file that is not a database, a database without the tables of an index, an empty one, a link leaving the repository, and shell syntax and quotes in the path, kind, `built_by`, name, module and unit | While the file is untrusted, no database is opened and no command is printed, shown by a test. Once trusted, the path stays inside the repository after links are resolved. The file is opened through Python's own `sqlite3`, read-only and immutable, stopped after 2 seconds, and only its table names and one `select 1 from refs limit 1` run. Nothing the file holds is printed. The commands come from templates and the path is quoted whole, and `built_by` is withheld until the file is trusted. What stays is that the commands an agent then runs open the file with `sqlite3` and `hiedb`, which Вивід does not control | |
| SEC-28 | **A project whose documents are private can still leak one in text the citation check never reads, such as a pull request written directly on GitHub, a title typed into a web form, or a commit made with the check not run.** | medium | citations, projects | read from the code, and tested that a staged line and a commit message or pull request text file citing a slice, a question or a register entry defined in the private documents are refused, bare or qualified, and a clean one passes | `vyd check citations --staged` and `--message <file>`. | SEC-30 | **`vyd install --project` registers a command in a client's settings, and a client runs it on every tool call.** | medium | install, hook | read from the code and tested 2026-11-05 in Claude Code on a scratch project: the hook is standard library only, took 33 ms, never returns a decision, and prints no decision on bad input.
