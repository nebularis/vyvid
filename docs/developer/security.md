# Security findings

**Unit type:** Register

What we have found that could harm a person using Вивід, how we know, and what closes it. `SECURITY.md` tells users the threat surface, and this register holds the findings behind it. A row is promoted to a security domain once one exists.

**Evidence** says how far a finding was proven: tested on a hostile domain, read from the code, or designed but not yet built. A row is open until its `Fixed in` cell is filled.

| ID | Finding | Severity | Surface | Evidence | Remediation | Fixed in |
|---|---|---|---|---|---|---|
| SEC-1 | **A manifest's `rules` may name any file, whose text is copied word for word into a generated skill.** | high | manifest, install | tested 2026-11-04, a fake secret outside the domain reached `SKILL.md` | every path a manifest names stays inside the domain's folder | 2026-11-04 |
| SEC-2 | **A manifest's family may be defined by a file outside the domain, whose rows are indexed and shown to an agent.** | high | manifest, index | tested 2026-11-04, `find` printed a row from outside the domain | as SEC-1 | 2026-11-04 |
| SEC-3 | **A symlink in a domain may lead a read outside its folder.** | medium | clone, index | tested 2026-11-04, a test shows `read_text` following a link out of the folder | refuse a link that leaves the folder | 2026-11-04 |
| SEC-4 | **A manifest sets its own git policy, so a domain's author may choose to be pulled at every start and pushed automatically.** | high | manifest, update | tested 2026-11-04, `pull=on-start` and `push=auto` were accepted | only the user's configuration sets `git` and `remote` | 2026-11-04 |
| SEC-5 | **A manifest's family pattern can hang a build by catastrophic backtracking.** | medium | manifest, index | tested 2026-11-04 on Python's `re`, `(C+)+$` ran past 4 seconds, and a manifest's pattern reaches `re.compile` unchecked | the `regex` package with a time limit, which disables the family and reports it | 2026-11-04 |
| SEC-6 | **A domain named `domain-review` could overwrite a core skill of that name.** | high | install | read from the code | a domain's skill and a core skill have separate prefixes | 2026-11-04 |
| SEC-7 | **A later push to a domain reaches agents with no review, since a pull changes the rules and skills they read.** | high | update | tested 2026-11-04, a pull that changed `rules.md`, `domain.toml` or a `SKILL.md` of a knowledge domain merged nothing and named the files, a register change fast-forwarded, and `vyd kb accept` refused without a terminal | hold changes to rules and skills of a domain the user did not write until the diff has been seen | 2026-11-04 |
| SEC-8 | **`vyd install` turns a domain's rules into agent instructions with no review.** | high | install | tested 2026-11-04, a knowledge domain got no skill and a generated one was removed, and `vyd context` withheld its rules, skills and recipe descriptions | install rules and skills only from domains the user's configuration marks as trusted | 2026-11-04 |
| SEC-9 | **A finding's text reaches an agent like any other text, so it can carry instructions.** | medium | results | tested 2026-11-04, find, read, node and a recipe's briefing labelled a knowledge domain's entries as data and named invisible Unicode and an HTML comment, and no control removes this wholly | label results as data from a named domain, and flag invisible Unicode and HTML comments | 2026-11-04 |
| SEC-10 | **A client approves `vyd recipe run` and never sees the glue command inside it.** | medium | glue | read from the code | `--dry-run` shows each command, and `--stop-at-glue`, or `[framework] glue = "stop"` which no flag overrides, stops at each glue step and prints its command for the agent to run through its own shell, so the client sees and approves each one | 2026-11-04 |
| SEC-11 | **Glue inherits the whole environment, including tokens and the SSH agent socket, with which it can act as the user.** | high | glue, credentials | read from the code, `subprocess.run` is given no `env`. Tested: a token and the SSH agent socket in the environment do not reach glue, a variable its step names does, and `mise exec` runs under the list | a minimal environment of named variables, with others passed only when a step names them in `env` | 2026-11-04 |
| SEC-12 | **Glue, an extractor and an installed package run with the user's full privileges, and can read `~/.ssh`, `~/.aws` and any other file.** | high | code, credentials | inherent, no cross-platform sandbox exists to apply. A command extractor gets a minimal environment, but still runs unsandboxed | state it to users, and run what is not trusted in a container | |
| SEC-13 | **A folder-local configuration would let a cloned repository declare glue that runs when a recipe does.** | high | glue, configuration | tested 2026-11-04, a configuration other than the user's own ran no glue and no command extractor until `vyd trust` recorded its hash, and a one-byte edit undid it. A repository's `vyvid.toml` was held the same way, with its hash recorded under the git common directory and its path, so a worktree of identical bytes needed no second trust and a branch that changed the file was asked again. It was refused when it set `code`, `git`, `remote` or `trust`, or named a path leaving the repository by name or through a link, and a refused file set aside only its project. Until trusted, its contract, skills and recipe descriptions were withheld and its entries labelled as data | an explicit trust step per folder, re-asked when the configuration changes | 2026-11-04 |
| SEC-14 | **`VYVID_CONFIG` redirects the whole configuration, so whatever sets the environment chooses what glue exists.** | medium | configuration | tested 2026-11-04, a configuration named by `VYVID_CONFIG` is treated as any other outside the user's own folder | apply the trust step to any configuration outside the user's own folder | 2026-11-04 |
| SEC-15 | **Glue's output and error text go to the agent, and so to the model's provider and the transcript.** | medium | glue, credentials | tested 2026-11-04, a fake token printed by glue on standard output and on standard error, and by a command extractor, reached neither the briefing nor the error | cap the error text, and redact what looks like a credential | 2026-11-04 |
| SEC-16 | **`vyd kb record` under an automatic push can publish a secret, since nothing scans what it stages.** | high | update, credentials | tested 2026-11-04, a fake token in a staged file refused the record and staged nothing, with the token absent from the message, by the built-in scan and by `gitleaks` | refuse to stage what looks like a credential | 2026-11-04 |
| SEC-17 | **A remote URL holding a token is stored in the configuration and printed by `vyd kb`.** | low | configuration, credentials | tested 2026-11-04, a password, a user part on https, a query and a known token format were refused, naming the host and never the URL | refuse a remote URL that holds a credential | 2026-11-04 |
| SEC-18 | **The index and the question logs are plain files under the user's default permissions, and a question may hold something sensitive.** | low | store, credentials | tested 2026-11-04 on POSIX, the store folder is 0700 and an existing one is tightened, the logs are 0600, and `logs = false` writes none | owner-only permissions, and a setting that turns the logs off | 2026-11-04 |
| SEC-19 | **An extractor's package would be installed with no pinned hash.** | high | code | designed, not built | a pinned hash, explicit consent, and no install on a pull | |
| SEC-20 | **One domain's refused manifest stops the whole configuration, so a careless or hostile push to a domain can stop `vyd` in every project on the next pull.** | medium | manifest, update | tested 2026-11-04, a refused manifest set aside only its domain and its descendants, `vyd config` listed them and exited non-zero, and the rest loaded | set aside only the domain at fault and report it, and hold a pull that would break its manifest | 2026-11-04 |
| SEC-21 | **`vyd trust` and `vyd kb accept` refuse unless standard input is a terminal, which is a speed bump and not a proof, since an agent given a pseudo-terminal could pass it.** | medium | trust | read from the code, and the tests prove only that a pipe and `/dev/null` are refused | none that holds in software alone. A check by the operating system's own authentication would need a platform each | |
| SEC-22 | **An agent that can run commands as the user can edit the user's configuration and set `trust = "own"`, or record trust itself.** | high | trust, configuration | inherent, the user's configuration is trusted because the user wrote it | the client's permission settings, which are outside Вивід. `SECURITY.md` says so | |
| SEC-23 | **The label and the begin and end lines around a knowledge domain's text are text, so a domain can print a fake end line and follow it with its own.** | low | results | read from the code | none yet. The label is advice to a reader that can still be persuaded, and the other controls do not rely on it | |
| SEC-24 | **A bare path in a manifest resolved against the working folder, so `defined = "notes.md"` read that file from wherever a command ran, passing the containment check, and a held update compared the wrong path and merged.** | high | manifest, index, update | tested 2026-11-04, a real clone merged a changed rule while the suite passed, since its tests used `self:` paths | a bare path means the scope's own folder, proven by tests with a file of the same name in the working folder | 2026-11-04 |
| SEC-25 | **A reviewer told to run nothing used a shell to decode a blob, since the client gave it one.** | medium | review | tested 2026-11-04, the first real run of the review skill, which found all 13 planted attacks, obeyed none and made one false report | `vyd install` writes the reviewer as an agent with read and search tools alone, and the audit prints what a blob decodes to. A definition takes effect in a new session, so that limit is written and not yet seen in use | |
